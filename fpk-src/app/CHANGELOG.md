# 变更日志

格式：最新版本在最上面；每节以 `## 版本号（日期）` 开头，下面用 `- ` 列条目。
打包时 `tools/sync_version.py` 会取最新一节，压缩成 fpk manifest 的 `changelog` 字段。

## 1.3.0（2026-10-29）

- 修复归因链路四处稳定落空：电源态键不一致、SMART 另插一条唤醒、fanotify 看不见容器、多成员盘只进第一块的环
- 修复电源态键：采样存的是 `/dev/sda`，diskstats 与面板查的是 `sda`，导致 `last_state` 永远 `unknown`、面板电源态恒为未知、「盘明明醒着」也拦不住
- SMART 只升级最近一次 diskstats 唤醒（回看一个轮询周期），不再用采样时刻另插一条；升级后自动重跑归因并回写嫌疑进程，消除「高置信 + 零嫌疑」
- 归因窗口改为「唤醒前 20 秒 + 唤醒后 3 秒」，排序改为「唤醒前最早的那笔」，唤醒前 2 秒内（上电期 / 涌入期）的样本单独归类、排在后面
- fanotify 改用 `FAN_MARK_FILESYSTEM`（按超级块分组、每组一个 fd）：容器 bind mount 里的访问同样可见，事件自带设备归属，路径解析不出来也不再丢
- 事件源优先级反转：内建 fanotify 优先，fatrace 退为备用（它只按挂载点打标记，看不见容器）
- 多成员盘（md / btrfs 多设备）共享挂载点时，样本进每一块盘的环，并标记「多盘歧义」；btrfs 成员关系从 `/sys/fs/btrfs/*/devices` 补齐
- 归因为空时扫描 `/proc/*/fd` 找谁持有 `/dev/sdX`（块层访问唯一线索），并在备注里注明；同时识别「smartctl 轮询自身把盘转醒」的情形
- 面板统计口径拆分：新增「解析不出设备 / 设备未监控 / 队列溢出 / 因盘活跃未记为唤醒」，`FAN_Q_OVERFLOW` 不再被静默丢弃
- `dwmctl probe` 新增「挂载点映射」与「文件系统级标记（容器覆盖）」两项检查；`dwmctl status` / `wakes` 显示归因阶段与歧义标记
- 事件源过滤修正：fanotify 的 comm 为空时 `ignore_comms` 原本完全不生效，现改为补全进程信息后再过滤，并覆盖子进程链

## 1.2.0（2026-10-27）

- 修复 fnOS 阵列挂载（/dev/md0 或 DM 挂到 /vol*）下访问事件无法归属到成员盘、导致全部唤醒「未捕获到访问事件」的问题：挂载映射现在穿透 md/DM 阵列，并新增 st_dev 兜底归属
- 新增按盘清除记录：面板磁盘卡片「清除」按钮、`POST /api/clear`、`dwmctl clear --dev sda`
- 面板新增事件产出统计：数据源显示「已接收/已归属/无法归属」事件数，事件源无产出或映射失败会直接在面板警示，不再静默
- 唤醒列表为空时的提示按实际故障（源无产出 / 映射失败 / 盘未休眠）区分

## 1.1.0（2026-10-27）

- 新增内建 fanotify 事件源：不装 fatrace 也能拿到「进程 → 文件 → 磁盘」归因
- 修复内置机械盘默认不被监控的问题（现按 rotational 自动纳入）
- 修复内核 5.10+ 上 block_dump 已失效导致的「全部唤醒无归因」
- 面板显示版本号；安装向导改为分步指导，明确使用前提与查看方式
- 版本号改为单一来源管理，打包时自动同步到应用包
- 安装包文件名带版本号（`diskwakemonitor_1.1.0_x86.fpk`），旧版本自动归档到 `dist/archive/`

## 1.0.0（2026-10-26）

- 首个版本：唤醒判定（diskstats）+ 电源态确认（SMART）+ 进程归因
- Web 面板：唤醒时间线、磁盘状态、阻止休眠的元凶排行、实时推送
- 命令行：probe / status / wakes / top / tail
- 飞牛应用包（fpk）：应用中心安装、向导配置、生命周期脚本
